2. Architecture

  Browser ──▶ Vercel (React frontend)
                 │  /api and /uploads proxied via rewrites in vercel.json
                 ▼
              Render (NestJS API) ──▶ PostgreSQL + PostGIS
                                  └─▶ Redis

The frontend proxies /api and /uploads to the Render API, so the browser only ever talks to one origin (the Vercel domain). This keeps the login/refresh cookie working without CORS or cross-site-cookie setup. Verified working: GET <vercel-url>/api/health → 200 through the proxy chain.

4. What Was Fixed (Root Cause of the Failed Build)

The Render build was failing with TS2307: Cannot find module './uploads/...' (6 errors). The cause was a .gitignore rule — uploads/, intended for the runtime file-storage folder — that also matched the source module apps/api/src/uploads/. Those 9 source files existed locally but had never been pushed to GitHub, so Render could not compile them.

Fix (commit 9953c05 on main):

  • Anchored the ignore rules to the real runtime paths (/apps/api/uploads/, /apps/api/uploads-private/) so they no longer swallow the source module.
  • Committed the 9 missing apps/api/src/uploads/ source files (uploads module, controller, constants, URL signer, and the storage strategies).

8. Known Free-Tier Limitations

  • API sleeps after ~15 min idle; first request after that takes ~50s to wake.
  • Ephemeral storage — uploaded images reset on redeploy. Set CLOUDINARY_URL for persistence.
  • Live chat (WebSockets) is not proxied by Vercel, so it is disabled in this setup. The rest of the app is unaffected.
